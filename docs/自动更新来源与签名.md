# 自动更新来源与签名

## 当前行为（2026-09-20）

本分支的更新来源为 `csdjk/codex-switcher`，与 Git 的 `origin` 一致。

桌面应用启动后，用原生 `getVersion()` 获取当前程序版本，读取本仓库 GitHub Releases 的最新正式发行版。仅发现更高版本时显示版本号、更新说明、明确的仓库来源以及“稍后／前往下载”按钮。点击后只打开本仓库对应的发行页，由用户自行下载安装。浏览器和局域网模式不检查桌面应用更新。

更新信息请求不携带账号信息、Authorization 或 Cookie，10 秒后超时，可随组件卸载取消。查询失败、GitHub 限流或断网时静默结束本次检查，不弹出“已是最新版”，也不回退到原项目。草稿、预发布、相同版本、旧版本和其他仓库的下载链接均不提示。

唯一的运行时仓库来源常量位于 `src/lib/appUpdates.ts`：

```text
UPDATE_REPOSITORY = csdjk/codex-switcher
API = https://api.github.com/repos/csdjk/codex-switcher/releases/latest
发布页 = https://github.com/csdjk/codex-switcher/releases
```

## 本次修复

原来的 README 已说明尚未配置本仓库独立签名，但主 Tauri 配置仍保留原项目的更新地址和公钥，启动时的组件也仍调用签名更新插件。CI 关闭了更新签名及 `latest.json` 上传，仅改文档没有关闭实际调用。

现在已移除原项目的 updater 配置、公钥、插件运行时注册及 `updater:default` 权限；本地与 CI 的 `createUpdaterArtifacts` 均为 `false`。不使用原项目安装包，不跳过签名检查，也没有生成或上传任何新密钥。

软件标识 `com.lampese.codex-switcher`、作者署名和进程兼容判断未改动，以避免在更新源修复中混入安装识别、数据路径迁移或署名变更。这些不是更新服务器地址。

## 后续恢复应用内自动安装的条件

“自动检查版本”和“自动下载安装”是两件事。本次实现前者；后者保持关闭。恢复签名更新前，需要完成以下整套配置：

1. 为本仓库建立并妥善备份独立的签名私钥；不要提交私钥到 Git，或把签名私钥写入客户端。
2. 将对应的公钥写入客户端，私钥和需要的密码配置到发布流水线的 Secrets。
3. 生成各平台更新产物与 `.sig`，上传只指向本仓库产物的 `latest.json`。
4. 检查新版元数据、产物、签名、公钥与平台标识一致后，再恢复插件注册、权限和安装按钮。
5. 从一份实际安装的旧版执行端到端升级验收，不能用“能打开链接”代替安装验证。

参考：Tauri Updater 官方文档 `https://v2.tauri.app/plugin/updater/`；GitHub Releases API 文档 `https://docs.github.com/en/rest/releases/releases`。
