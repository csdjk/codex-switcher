# 订阅日期修复验收

日期：2026-09-09。

## 问题与根因

用户账单页显示 2026-10-08 自动续订，账号卡片却显示 2026-08-31 已到期。

旧逻辑将导入登录凭证中的 `chatgpt_subscription_active_until` 保存为订阅到期时间，缺失时还会再次从凭证回退取值。页面自动轮询只更新额度。手动查询虽能读取实时权益，但只解析了 `entitlement.expires_at`，没有读取账单续订字段 `entitlement.renews_at`。

本次通过现有 Rust HTTP 客户端读取真实账号的账户查询接口，返回：

| 字段 | UTC 值 | 含义 |
| --- | --- | --- |
| `entitlement.renews_at` | `2026-10-08T04:28:49Z` | 下次续订，与账单日期一致 |
| `entitlement.expires_at` | `2026-10-09T05:28:49Z` | 权益截止，不能当成续订日 |

两个日期均来自真实接口，没有根据截图手动覆盖日期，也没有对权益截止时间做减一天之类的推算。

## 修复范围

- 新增实时订阅元数据，分别保存续订、权益截止和查询时间。旧账号库无需手动迁移；缺少新字段时显示未验证，并自动查询。
- 账号卡片优先显示“下次续订”；接口没有续订日期时显示“权益截止”。接口没有任何日期时明确显示不可用。
- 返回账号信息时不再将旧凭证日期作为已验证日期。接口失败会保留明确的同步错误；如果已有成功查询缓存，日期标注“上次查询”，提示中保留错误原因。
- 页面打开和手动刷新会同步订阅信息；导入新账号后自动同步，运行期间至少每小时更新一次。订阅同步失败不会阻断额度查询。
- 元数据查询不再无条件强制刷新 OAuth 凭证。订阅只匹配所请求的账号，找不到时返回错误，不能随意取其他账号日期。
