# 额度与账号体验优化验收

日期：2026-09-21。保留当前工作区已有改动；本轮修改前副本位于 `Temp/usage-optimization/before/`。

## 行为变化

1. 总览和账号卡片明确显示缓存额度及获取时间。自动预热排除缓存；定时预热在发送前重新查询，失败或返回缓存时跳过该账号。
2. 额度请求与订阅同步并行，当前账号优先进入查询队列，各账号完成后立即显示。同一窗口的重叠刷新共享请求；Rust 层进一步合并主窗口、托盘等入口对相同账号凭据的并发查询。仅共享进行中的查询，不把历史结果当实时结果。
3. 剩余额度排序取五小时、每周两个已知窗口的较小剩余值。两个排序方向均把实时结果放在缓存前，未知或失败放最后；修正缺失日期比较产生 NaN 的问题。
4. 统计首次展开立即加载，重置券与统计共用进行中的请求和五分钟内的成功结果。手动刷新统计绕过历史结果。统计列数随卡片宽度变化，数值不再被省略号截断。
5. 备用账号默认紧凑显示，保留身份、额度、重置倒计时、更新时间及切换入口。“更多操作”展开订阅日期、重置券、余额、预热、统计和删除等内容；当前账号保留完整显示。

## 验证

- `npm run build`：通过。
- `node --experimental-strip-types --test tests/usageModel.test.ts tests/i18n.test.ts tests/resetCredits.test.ts`：11 项通过。
- `cargo test --manifest-path src-tauri/Cargo.toml --lib --offline`：76 项通过，含并发共享、失败后重试、独立账号和取消后恢复。
- `cargo check --manifest-path src-tauri/Cargo.toml --bins --offline`：通过，存在原有 6 条未使用项警告。
- `tests/usageOptimization.browser.cjs`：34 项记录通过，包括 32 个界面状态及 2 组行为验证。手动保持订阅和慢账号请求未返回，确认当前账号额度已显示；单账号和全部刷新重叠时仅有一个额度请求；首次展开统计复用同一成功查询，手动刷新产生新请求；推进虚拟时钟后缓存未触发自动或定时预热。
- `tests/subscription.browser.cjs`：5 种订阅状态 × 4 个视口通过，包括导入后展开订阅详情和手动同步。
- 本轮修改的 Git 空白检查通过。

界面测试使用 Windows、Playwright 1.62.1 的 Chromium headless、Vite `http://127.0.0.1:3221`，DPR=1。视口为 1000×800、320×568、375×667、390×844；后三者启用移动端模式。覆盖中英文、深浅色、备用账号收起与展开、缓存及 API Key 不支持额度的状态。通过页面横向溢出和统计数值裁切断言，并人工查看代表截图的间距、层级、换行和可读性。本轮没有参考图还原目标，不作像素相似度声明。

所有账号和网络响应均为隔离测试数据，不读取真实凭据，也未发送真实预热请求。这里的刷新结论来自受控请求时序，不是生产网络速度基准。未替换已安装桌面应用，未验证真实账号联网与原生托盘联动，未发布或推送 Git。
