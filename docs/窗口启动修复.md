# Windows 窗口启动与重复打开修复

> 以下保留开发与本地预览阶段的验收记录；v0.2.19 的安装说明和发布前验证见 [v0.2.19 发布说明](发布说明/v0.2.19.md)。

日期：2026-10-16。

## 现场原因

旧安装版仍驻留后台时，打开 Token 速度预览版，只产生了事件消息窗口，没有创建真正的 `Tauri Window` 主窗口。仅看进程存在或 `MainWindowHandle` 非零会误判启动成功：其中有一个只有 16×16 的内部事件窗口。

本机对照验证：为预览版临时指定独立 WebView 缓存可创建窗口；通过旧版原生菜单的“退出”正常退出旧版后，预览版使用原来的默认缓存也成功显示主窗口。没有删除缓存、重置账号或终止 Codex 任务。主窗口原生截图已确认 Token 输出速度面板实际加载，能显示本地日志数据。

## 代码修复

- 将官方 `tauri-plugin-single-instance` 注册为第一个插件，在创建其他插件和 WebView 之前识别重复启动。
- 再次打开程序时唤起已有窗口：隐藏托盘弹窗、显示主窗口、取消最小化并聚焦，不创建第二套 WebView。
- 回调通过主线程执行窗口操作，不处理传入参数，不切换账号，不终止其他进程。
- 固定插件为 `2.4.5`，保持项目现有 Tauri `2.10.3` 及其他依赖版本不变。锁文件仅新增这一个包。选择该版本是为了避免因启动修复升级整个桌面运行时。

参考：官方 [单实例插件说明](https://v2.tauri.app/zh-cn/plugin/single-instance/) 与 [发布记录](https://v2.tauri.app/release/single-instance/)。

## 验证

`tests/windowStartup.ps1` / `npm run test:window-startup` 检查真正的 Windows 主窗口，而不是内部消息句柄。验证重复打开、最小化后重开、关闭到托盘后重开；重复实例应退出，原进程继续保留且主窗口可见。测试完成后保留应用打开。

验收结果：

- Windows Release 构建通过；保留原有平台条件编译警告，没有升级其他桌面依赖。
- Rust 全部 95 项测试通过，前端逻辑 31 项测试通过。
- 已运行实例与冷启动分别验证上述 3 种操作，全部通过；第二实例退出，原实例保持唯一，窗口可见、未最小化且处于前台。
- 冷启动测试等待真正的 WebView 渲染子窗口建立后再操作，避免将初始化中的空壳窗口误当成可交互界面。
- 使用默认缓存启动，不依赖隔离缓存、调试端口或开发服务器。修复后的原生截图位于 `Temp/startup-qa/real-startup-fixed.png`，只截取顶部与测速区，不包含账号详情。
- 报告：`Temp/startup-qa/window-startup-report.json`（冷启动）、`window-startup-warm-report.json`（已运行实例）。

## 预览与边界

预览程序仍为 `Temp/token-speed-preview/codex-switcher.exe`，未替换原安装目录。旧安装版还不具备单实例处理，不能指望新代码约束未更新的旧二进制；使用预览版时应先退出旧版。本次已经通过旧版自身的退出菜单完成这一操作。

不更改账号、认证文件、Codex 配置或用户的界面偏好。未发布、未推送 Git，未进行 macOS/Linux 实机验收。
